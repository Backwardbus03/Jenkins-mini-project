# Week 10: Continuous Testing in Jenkins

This document details the integration of the **Rent Payment Reminder Portal Selenium automated regression test suite** into the **Jenkins CI/CD pipeline**, configuring test reports, implementing quality gates to prevent broken deployments, simulating a defect to verify deployment halt, and correcting the defect with verified pipeline rerun.

---

## 1. Executive Summary & Objective

Continuous Testing ensures that automated test suites are executed as an automated quality gate within the CI/CD pipeline rather than as a disconnected manual activity. In this phase:

1. **Selenium Test Suite Integration**: Embedded headless Chrome tests (10 test scenarios covering 5 critical user journeys) are executed automatically in Jenkins via Maven (`mvn test`).
2. **Automated Test Reporting**: Jenkins parses JUnit XML reports generated by Maven Surefire (`target/surefire-reports/*.xml`), providing graphical test trend charts, duration breakdown, and drill-down into assertion failures.
3. **Deployment Halting Quality Gate**: The pipeline enforces a fail-fast policy. If any Selenium scenario fails, the pipeline terminates immediately, preventing the `Package` and `Deploy` stages from executing.
4. **Defect Simulation & Evidence**: A deliberate defect is introduced to demonstrate pipeline failure, deployment stoppage, and failure screenshot capture.
5. **Defect Correction & Rerun**: The defect is resolved, committed to version control, and the pipeline is rerun to demonstrate 100% pass rate and successful hot-deployment to Apache Tomcat.

## 2. Declarative Pipeline Design (`Jenkinsfile`)

The pipeline defines an automated workflow containing sequential stages:

```
 ┌────────────┐     ┌───────────┐     ┌──────────┐     ┌───────────┐     ┌──────────┐
 │  Checkout  │ ──> │  Compile  │ ──> │   Test   │ ──> │  Package  │ ──> │  Deploy  │
 └────────────┘     └───────────┘     └──────────┘     └───────────┘     └──────────┘
                                           │
                                  [Test Fails? (Red)]
                                           │
                                           ▼
                                 ┌───────────────────┐
                                 │  HALT DEPLOYMENT  │
                                 │ (Package/Deploy   │
                                 │    SKIPPED)       │
                                 └───────────────────┘
```

### Complete `Jenkinsfile` Specification

```groovy
pipeline {
    agent any

    tools {
        jdk 'JDK-21'
        maven 'Maven-3'
    }

    parameters {
        choice(name: 'DEPLOY_ENV', choices: ['dev', 'staging', 'prod'], description: 'Select the environment to deploy to')
        string(name: 'TOMCAT_URL', defaultValue: 'http://localhost:8080/manager/text', description: 'Tomcat Manager API URL')
    }

    environment {
        SPRING_PROFILES_ACTIVE = "${params.DEPLOY_ENV}"
    }

    stages {
        stage('Checkout') {
            steps {
                echo 'Checking out the source code...'
                checkout scmGit(branches: [[name: '*/main']], extensions: [], userRemoteConfigs: [[url: 'https://github.com/Backwardbus03/Jenkins-mini-project.git']])
            }
        }

        stage('Compile') {
            steps {
                echo "Compiling the application for environment: ${params.DEPLOY_ENV}..."
                bat 'mvn clean compile'
            }
        }

        stage('Test') {
            steps {
                echo 'Executing Selenium Automated Regression Suite...'
                // If any test fails, Maven exits with non-zero exit code (1), halting the pipeline
                bat 'mvn test'
            }
        }

        stage('Package') {
            steps {
                echo 'Packaging the application into a WAR file...'
                bat 'mvn package -DskipTests'
            }
        }

        stage('Deploy') {
            steps {
                echo "Deploying to Tomcat server at ${params.TOMCAT_URL}..."
                bat '''
                    copy /Y target\\rent-reminder-portal.war "C:\\DevTools\\apache-tomcat\\apache-tomcat-11.0.24\\webapps\\rent-reminder-portal.war"
                '''
            }
        }
    }

    post {
        always {
            echo 'Publishing test reports and archiving build artifacts...'
            // Publishes JUnit test results to Jenkins dashboard
            junit allowEmptyResults: true, testResults: 'target/surefire-reports/*.xml'
            // Archives deployable WAR, failure screenshots, and custom HTML reports
            archiveArtifacts artifacts: 'target/*.war, target/screenshots/*.png, target/selenium-reports/**', allowEmptyArchive: true, fingerprint: true
        }
        success {
            echo 'Continuous Testing & Deployment Successful!'
        }
        failure {
            echo 'Pipeline Failed: Deployment halted due to test failure or compilation error.'
        }
    }
}
```

### Stage Responsibilities
1. **`Checkout`**: Clones the verified source revision from the remote GitHub repository.
2. **`Compile`**: Runs `mvn clean compile` using Jenkins tool `Maven-3` and `JDK-21` to validate syntax and compile classes into `target/classes`.
3. **`Test` (Continuous Quality Gate)**:
   - Invokes `mvn test` which boots the Spring Boot embedded container on a random port and runs the 10 Selenium test scenarios in headless Chrome.
   - If an assertion fails, Surefire records the failure in `target/surefire-reports/TEST-*.xml` and exits with code 1.
   - Jenkins detects non-zero exit and immediately aborts subsequent execution.
4. **`Package`**: Bundles the application into `target/rent-reminder-portal.war`. Note that `-DskipTests` is used here only because tests already passed in the preceding `Test` stage.
5. **`Deploy`**: Transcribes the tested WAR file into Tomcat's `webapps` directory (`C:\DevTools\apache-tomcat\apache-tomcat-11.0.24\webapps\rent-reminder-portal.war`) for hot auto-deployment.
6. **`post` Actions**:
   - `junit`: Collects all Surefire XML test files and integrates them into Jenkins Test Result interface with pass/fail counts and history graphs.
   - `archiveArtifacts`: Persists the WAR artifact and any failure screenshots captured in `target/screenshots/`.

## 3. Deliberately Introduced Defect (Experiment & Evidence)

To validate that the pipeline effectively functions as a quality gate, a defect was deliberately introduced into the portal authentication UI.

### 3.1 Defect Details
- **Target File:** `src/main/resources/templates/login.html` (Line 18)
- **Original Code:**
  ```html
  <div th:if="${param.error}" class="alert alert-error">⚠️ Invalid email or password. Please try again.</div>
  ```
- **Defective Code Introduced:**
  ```html
  <div th:if="${param.error}" class="alert alert-error">⚠️ Something went wrong. System error.</div>
  ```
- **Failing Scenario:** `Journey1_OwnerAuthenticationTest.java`
  - Scenario: `testOwnerLoginInvalidCredentials()`
  - Assertion:
    ```java
    assertTrue(loginPage.getErrorMessage().contains("Invalid email or password"),
            "Error message should alert the user to invalid credentials");
    ```

### 3.2 Defect Commit
The defect was committed to the repository:
```bash
git add src/main/resources/templates/login.html
git commit -m "test(defect): deliberately alter login error message to simulate regression"
git push origin feature/tenant-portal
```

## 6. How to Run the Pipeline in Jenkins (Step-by-Step)

### Step 1: Create or Configure the Pipeline Job
1. Open Jenkins at `http://localhost:8080`.
2. Click **New Item** on the dashboard.
3. Enter `rent-reminder-pipeline` and choose **Pipeline**. Click **OK**.
4. Scroll to the **Pipeline** configuration section:
   - **Definition:** Select `Pipeline script from SCM`.
   - **SCM:** Choose `Git`.
   - **Repository URL:** `https://github.com/Backwardbus03/Jenkins-mini-project.git`.
   - **Branch Specifier:** `*/main` (or `*/feature/tenant-portal`).
   - **Script Path:** `Jenkinsfile`.
5. Click **Save**.

### Step 2: Run the Pipeline
1. In the left navigation, click **Build with Parameters**.
2. Select `DEPLOY_ENV` (e.g. `dev`).
3. Click **Build**.

### Step 3: Inspect the Test Reports and Artifacts
1. Click the build number (e.g. `#11`) in Build History.
2. Click **Test Result** in the left menu to view scenario pass rates and execution timings.
3. Under **Build Artifacts**, review the archived files:
   - `rent-reminder-portal.war`
   - `target/screenshots/` (screenshots if tests failed)
   - `target/selenium-reports/index.html` (interactive HTML report)

### Step 4: Verify Live Tomcat Deployment
1. Verify Tomcat has deployed the WAR:
   `http://localhost:8081/rent-reminder-portal/tenants` (or configured Tomcat port).
2. The application should load cleanly with the latest tested changes.
